# Пароли и роли сотрудников

Учётные записи сотрудников — Django User (`/admin/auth/user/`). Пользователи мобильного сервиса и их роли в таблице `roles` — отдельные сущности.

## Смена пароля

Войти нужной учётной записью и открыть `/admin/password_change/`. Понадобится текущий пароль, затем новый пароль дважды.

Если войти невозможно, выполнить внутри контейнера `admin_service`:

```sh
python manage.py changepassword admin
```

Команда запрашивает новый пароль скрытым вводом. Смена пароля не требует изменения кода или пересборки контейнера. Не передавать пароль аргументом командной строки.

## Новая роль

После развёртывания кода суперпользователь открывает «Роли админки» (`/admin/auth/group/`), нажимает «Добавить», указывает название и отмечает «Выдать все права сервиса».

Флажок заменяет список прав всеми установленными правами сервиса, включая управление политиками, поддержку и отправку push. Учётные записи администраторов доступны только для просмотра. Если флажок не отмечен, сохраняется вручную выбранный список прав.

Альтернатива — создание роли командой внутри контейнера:

```sh
python manage.py create_service_role --name 'Управляющий сервисом'
```

Команда не изменяет уже существующую роль. Создание новых таблиц и миграция данных для этой функции не требуются: используются стандартные Django Group и Permission.

## Назначение сотруднику

Суперпользователь открывает «Администраторы», создаёт сотрудника или редактирует существующего, включает «Активный» и «Статус персонала», отключает «Статус суперпользователя» и выбирает новую группу. Индивидуальные разрешения сотрудника суммируются с разрешениями всех его групп.

Не назначать новую роль учётной записи `admin` вместо статуса суперпользователя: эта учётная запись остаётся владельцем и управляет сотрудниками и ролями.

## Изменение и удаление

Суперпользователь может просматривать, создавать, переименовывать и удалять роли, менять набор их прав. Удаление группы снимает её права с участников, но не удаляет учётные записи. Остальные группы и индивидуальные разрешения продолжают действовать.

Создание, изменение и удаление администраторов и групп, а также сброс чужого пароля доступны только суперпользователю — даже если сотруднику вручную выдали соответствующие `auth`-разрешения. Смена собственного пароля разрешена каждому сотруднику.

Старые группы `Admin` и `Operator` сохраняют прежние специальные доступы. Для новых настраиваемых ролей использовать другие названия и назначать права явно. Права на новые модели, появившиеся при следующем развёртывании, можно добавить повторным сохранением роли с флажком «Выдать все права сервиса».
